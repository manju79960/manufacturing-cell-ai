# Teaching an AI Agent to Operate a Manufacturing Cell

A software-only virtual manufacturing-cell case study with a React dashboard, FastAPI backend, Q-learning agent, action validation, event log, metrics, and emergency stop.

## Features
- Virtual two-machine workflow: Load → Start Machine 1 → Process → Transfer → Start Machine 2 → Process → Unload.
- Q-learning training endpoint and reward chart.
- Step-by-step AI operation.
- Manual demonstration controls.
- Invalid-action blocking and penalties.
- Emergency stop that turns off both simulated machines.
- Live status and metrics API.

> **Scope and safety:** This is an educational software simulation only. It does not control PLCs, industrial robots, or physical equipment. The dashboard's simulation metrics are generated by the application and should not be presented as real factory results.

## Run locally

### 1. Backend
Install Python 3.10+.

```bash
cd backend
python -m venv .venv
```

Windows PowerShell:
```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

macOS/Linux:
```bash
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

Backend API: `http://127.0.0.1:8000`  
Interactive API docs: `http://127.0.0.1:8000/docs`

### 2. Frontend
Open a second terminal:

```bash
cd frontend
npm install
```

Create `frontend/.env` with:
```env
VITE_API_URL=http://127.0.0.1:8000
```

Then run:
```bash
npm run dev
```

Open the URL printed by Vite, usually `http://localhost:5173`.

## API endpoints
| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/status` | Cell state and training status |
| POST | `/api/reset` | Reset the simulation |
| POST | `/api/train` | Train Q-learning agent; JSON: `{"episodes":500}` |
| POST | `/api/step` | Let the agent choose and perform one action |
| POST | `/api/manual-action` | Demonstrate an action; JSON: `{"action":"load"}` |
| POST | `/api/emergency-stop` | Stop both simulated machines |
| GET | `/api/metrics` | Reward and safety metrics |

## Publish source to GitHub
1. Create a new **public** repository on GitHub, for example `manufacturing-cell-ai`.
2. Extract this folder and open a terminal inside it.
3. Run:
```bash
git init
git add .
git commit -m "Build AI manufacturing cell simulation"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/manufacturing-cell-ai.git
git push -u origin main
```
Replace `YOUR-USERNAME` with your GitHub username. Do not commit passwords, API keys, or private credentials.

## Deploy backend on Render
1. Push the repository to GitHub.
2. In Render, create a **New Web Service** and connect the repository.
3. Set **Root Directory** to `backend`.
4. Build command: `pip install -r requirements.txt`
5. Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
6. Deploy and copy the service URL, e.g. `https://your-service.onrender.com`.
7. Test `https://your-service.onrender.com/` and `/docs`.

## Deploy frontend on Vercel
1. Import the same GitHub repository into Vercel.
2. Set **Root Directory** to `frontend`.
3. Add environment variable:
   - Name: `VITE_API_URL`
   - Value: your deployed Render backend URL, without a trailing slash.
4. Deploy and open the Vercel URL.
5. If the frontend says it cannot connect, verify the Render service is awake and the environment variable is correct; then redeploy the frontend.

The backend currently allows cross-origin requests from any origin to simplify the first deployment. Before a public production release, restrict `allow_origins` in `backend/main.py` to your exact Vercel URL.
